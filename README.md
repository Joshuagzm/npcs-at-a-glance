# NPC Management

A full-stack starter for managing NPCs (non-player characters): a React + TypeScript SPA talking to a .NET 10 Web API. The backend ships with a working CRUD API at `/api/npcs` backed by an in-memory store, and the frontend dev server proxies API calls to it, so the two run together out of the box.

## Tech stack

| Layer | Tech |
| --- | --- |
| Frontend | React 19, TypeScript, Vite 8, yarn |
| Routing | TanStack Router (file-based, type-safe) |
| Styling / UI | Tailwind CSS v4, shadcn/ui (radix base, Nova preset, Geist font) |
| Linting | ESLint (flat config) + Prettier |
| Backend | .NET 10 Web API, controllers + domain + repository layering |

## Project structure

```
frontend/
  src/
    routes/              # TanStack Router file-based routes
      __root.tsx         #   shared layout (nav header + <Outlet />)
      index.tsx          #   home page at "/"
    routeTree.gen.ts     # generated by the router plugin — do not edit
    components/ui/       # shadcn/ui components
    lib/utils.ts         # cn() class-merge helper
    index.css            # Tailwind import + shadcn theme variables
  vite.config.ts         # router plugin, tailwind, @ alias, /api proxy

backend/
  NpcManagement.slnx     # solution (new .NET 10 XML format)
  NpcManagement.Api/     # HTTP layer: controllers, request contracts, DI wiring
  NpcManagement.Domain/  # core: entities + repository interfaces (no dependencies)
  NpcManagement.Infrastructure/  # repository implementations (in-memory for now)
```

Dependencies point inward: `Api → Infrastructure → Domain`. The domain layer knows nothing about HTTP or storage, so swapping the in-memory repository for a real database only touches `Infrastructure` and one DI registration.

## Prerequisites

- Node.js 20+ and yarn (corepack works: `corepack enable`)
- .NET 10 SDK (`dotnet --list-sdks` should show a `10.x` entry)

## Running the app

Start the backend first, then the frontend:

```sh
# Terminal 1 — API on http://localhost:5000
cd backend
dotnet run --project NpcManagement.Api --launch-profile http

# Terminal 2 — frontend on http://localhost:5173
cd frontend
yarn
yarn dev
```

The Vite dev server proxies `/api/*` to `http://localhost:5000`, so frontend code can just `fetch('/api/npcs')` — no CORS setup needed in development.

Other useful commands:

```sh
# frontend
yarn build      # type-check (tsc -b) + production build to dist/
yarn preview    # serve the production build locally

# backend
cd backend
dotnet build NpcManagement.slnx
```

## Linting & formatting

```sh
cd frontend
yarn lint            # ESLint (typescript-eslint, react-hooks, react-refresh)
yarn format          # Prettier — write changes
yarn format:check    # Prettier — check only (good for CI)
```

Notes on the ESLint config (`eslint.config.js`):

- `src/routeTree.gen.ts` is ignored everywhere (generated file).
- The `react-refresh/only-export-components` rule is disabled for `src/components/ui/**` (shadcn exports helpers like `buttonVariants` next to components) and `src/routes/**` (TanStack Router's plugin manages HMR for route files itself). Don't "fix" lint by restructuring those files.

## Adding shadcn/ui components

From `frontend/`:

```sh
npx shadcn@latest add dialog          # one component
npx shadcn@latest add table badge     # several at once
```

Components land in `src/components/ui/` and are yours to edit — shadcn copies source code rather than installing a package. Browse what's available at https://ui.shadcn.com/docs/components or with `npx shadcn@latest search`.

Import them via the `@` alias:

```tsx
import { Button } from '@/components/ui/button'
```

Theme colours live as CSS variables in `src/index.css` (`:root` for light, `.dark` for dark mode — toggle by putting the `dark` class on `<html>`).

## Adding pages (routes)

Create a file in `src/routes/` and the router plugin generates the route while `yarn dev` is running:

```tsx
// src/routes/npcs.tsx  →  available at /npcs
import { createFileRoute } from '@tanstack/react-router'

export const Route = createFileRoute('/npcs')({
  component: NpcsPage,
})

function NpcsPage() {
  return <div>NPC list goes here</div>
}
```

Naming conventions: `npcs.$npcId.tsx` for path params (`/npcs/:npcId`), `__root.tsx` for the shared layout. Links are type-checked: `<Link to="/npcs">` won't compile if the route doesn't exist.

## The API

| Method | Route | Description |
| --- | --- | --- |
| GET | `/api/npcs` | List all NPCs |
| GET | `/api/npcs/{id}` | Get one NPC |
| POST | `/api/npcs` | Create (name + role required, level 1–100) |
| PUT | `/api/npcs/{id}` | Full update |
| DELETE | `/api/npcs/{id}` | Delete |

- Sample requests live in `backend/NpcManagement.Api/NpcManagement.Api.http` — runnable directly from VS Code (REST Client extension) or Rider/Visual Studio.
- An OpenAPI document is served at `http://localhost:5000/openapi/v1.json` in development.
- Storage is **in-memory** — data resets on every API restart. To persist for real, implement `INpcRepository` (e.g. with EF Core) in `Infrastructure` and change the registration in `NpcManagement.Api/Program.cs`.

## Adding a new API resource

Follow the same shape as the NPC slice:

1. `Domain/Entities/Thing.cs` — the entity.
2. `Domain/Repositories/IThingRepository.cs` — the interface.
3. `Infrastructure/Repositories/InMemoryThingRepository.cs` — the implementation.
4. `Api/Contracts/ThingRequests.cs` — request records with validation attributes.
5. `Api/Controllers/ThingsController.cs` — the controller.
6. Register the repository in `Api/Program.cs`.
