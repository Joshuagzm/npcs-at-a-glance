# NPC Management

> An experiment in building a full-stack web application with [Claude Code](https://claude.com/claude-code).

This project is, first and foremost, a playground: an end-to-end app — React + TypeScript on the front, a .NET 10 Web API and Postgres on the back, with AI portrait generation wired in — built collaboratively with Claude Code to see how far an agentic coding workflow goes across the whole stack.

## The idea

The app was born at the table. Running tabletop games like **D&D 5e**, the party never sticks to the script — they wander off and start chatting up the random barkeep, the dockworker, the guard you mentioned once in passing. As a GM, two pain points come up again and again:

- **Names on the spot.** You need a believable name *right now*, and "uh… Bob?" breaks the spell.
- **Giving NPCs a life of their own.** A name isn't a character. The ones the party remembers have their own motives, likes and dislikes, and little quirks — and improvising all of that under pressure is hard.

And then there's the problem that outlasts the session: **continuity.** Three weeks later the party walks back into that tavern. Who was that bartender? What did she want? What did she think of the rogue who stiffed her on a tab? Without notes, that texture evaporates.

## What it solves

NPC Management is a place to **create, flesh out, and remember** the people your party meets:

- Generate or jot down **names** so you're never caught flat-footed.
- Capture what makes each NPC tick — **motives, likes, dislikes, and characteristics** — so they read as a person, not a stat line.
- Generate an **AI portrait** so there's a face to put to the name.
- Organise NPCs **by location**, with notes per place, so when the party returns somewhere you can pull up exactly who lives there and what they were up to.

The goal is to take the improv load off the GM in the moment, and to keep the world consistent between sessions.

## Tech stack

| Layer | Tech |
| --- | --- |
| Frontend | React 19, TypeScript, Vite 8, yarn |
| Routing | TanStack Router (file-based, type-safe) |
| Styling / UI | Tailwind CSS v4, shadcn/ui (radix base, Nova preset, Geist font) |
| Linting | ESLint (flat config) + Prettier |
| Backend | .NET 10 Web API, controllers + domain + repository layering |
| Persistence | PostgreSQL (NPCs); locations currently in-memory |
| AI portraits | Local Stable Diffusion (Forge) txt2img API |

## Project structure

```
frontend/
  src/
    routes/              # TanStack Router file-based routes
      __root.tsx         #   shared layout (nav header + <Outlet />)
      index.tsx          #   home page at "/"
      locations.tsx      #   locations + the NPCs found in them
      settings.tsx       #   portrait-generation settings
    routeTree.gen.ts     # generated by the router plugin — do not edit
    components/ui/        # shadcn/ui components
    lib/utils.ts          # cn() class-merge helper
    index.css             # Tailwind import + shadcn theme variables
  vite.config.ts          # router plugin, tailwind, @ alias, /api proxy

backend/
  NpcManagement.slnx     # solution (new .NET 10 XML format)
  NpcManagement.Api/     # HTTP layer: controllers, request contracts, DI wiring
  NpcManagement.Domain/  # core: entities + repository interfaces (no dependencies)
  NpcManagement.Infrastructure/  # repository implementations (Postgres + in-memory)
```

Dependencies point inward: `Api → Infrastructure → Domain`. The domain layer knows nothing about HTTP or storage, so swapping a repository implementation only touches `Infrastructure` and one DI registration.

## Prerequisites

- Node.js 20+ and yarn (corepack works: `corepack enable`)
- .NET 10 SDK (`dotnet --list-sdks` should show a `10.x` entry)
- PostgreSQL, for NPC persistence
- A local [Stable Diffusion WebUI Forge](https://github.com/lllyasviel/stable-diffusion-webui-forge) instance running with `--api`, for portrait generation (optional — the rest of the app works without it)

## Running the app

Start the backend first, then the frontend:

```sh
# Terminal 1 — API on http://localhost:5000
cd backend
dotnet run --project NpcManagement.Api --launch-profile http

# Terminal 2 — frontend on http://localhost:5173
cd frontend
yarn
yarn dev
```

The Vite dev server proxies `/api/*` to `http://localhost:5000`, so frontend code can just `fetch('/api/npcs')` — no CORS setup needed in development.

For AI portraits, have Forge running locally with its API enabled (`--api`). Generation parameters (model, VAE, seed, etc.) are configurable from the in-app **Settings** page.

Other useful commands:

```sh
# frontend
yarn build      # type-check (tsc -b) + production build to dist/
yarn preview    # serve the production build locally
yarn test       # Vitest

# backend
cd backend
dotnet build NpcManagement.slnx
```

## Linting & formatting

```sh
cd frontend
yarn lint            # ESLint (typescript-eslint, react-hooks, react-refresh)
yarn format          # Prettier — write changes
yarn format:check    # Prettier — check only (good for CI)
```

Notes on the ESLint config (`eslint.config.js`):

- `src/routeTree.gen.ts` is ignored everywhere (generated file).
- The `react-refresh/only-export-components` rule is disabled for `src/components/ui/**` (shadcn exports helpers like `buttonVariants` next to components) and `src/routes/**` (TanStack Router's plugin manages HMR for route files itself). Don't "fix" lint by restructuring those files.

## Adding shadcn/ui components

From `frontend/`:

```sh
npx shadcn@latest add dialog          # one component
npx shadcn@latest add table badge     # several at once
```

Components land in `src/components/ui/` and are yours to edit — shadcn copies source code rather than installing a package. Browse what's available at https://ui.shadcn.com/docs/components or with `npx shadcn@latest search`.

Import them via the `@` alias:

```tsx
import { Button } from '@/components/ui/button'
```

Theme colours live as CSS variables in `src/index.css` (`:root` for light, `.dark` for dark mode — toggle by putting the `dark` class on `<html>`).

## Adding pages (routes)

Create a file in `src/routes/` and the router plugin generates the route while `yarn dev` is running:

```tsx
// src/routes/npcs.tsx  →  available at /npcs
import { createFileRoute } from '@tanstack/react-router'

export const Route = createFileRoute('/npcs')({
  component: NpcsPage,
})

function NpcsPage() {
  return <div>NPC list goes here</div>
}
```

Naming conventions: `npcs.$npcId.tsx` for path params (`/npcs/:npcId`), `__root.tsx` for the shared layout. Links are type-checked: `<Link to="/npcs">` won't compile if the route doesn't exist.

## The API

| Method | Route | Description |
| --- | --- | --- |
| GET | `/api/npcs` | List all NPCs |
| GET | `/api/npcs/{id}` | Get one NPC |
| POST | `/api/npcs` | Create (name required; level 1–100, defaults to 1) |
| PUT | `/api/npcs/{id}` | Full update |
| DELETE | `/api/npcs/{id}` | Delete |
| POST | `/api/npcs/portrait` | Generate an AI portrait (returns the image + seed used); 502 if the generator is unreachable |

| Method | Route | Description |
| --- | --- | --- |
| GET | `/api/locations` | List all locations |
| GET | `/api/locations/{id}` | Get one location |
| POST | `/api/locations` | Create (name required; optional notes) |
| PUT | `/api/locations/{id}` | Full update (name + notes) |
| DELETE | `/api/locations/{id}` | Delete |

- Sample requests live in `backend/NpcManagement.Api/NpcManagement.Api.http` — runnable directly from VS Code (REST Client extension) or Rider/Visual Studio.
- An OpenAPI document is served at `http://localhost:5000/openapi/v1.json` in development.
- NPCs persist to **PostgreSQL**. Locations are still **in-memory** and reset on API restart — back them up before restarting if you care about them.

## Adding a new API resource

Follow the same shape as the NPC slice:

1. `Domain/Entities/Thing.cs` — the entity.
2. `Domain/Repositories/IThingRepository.cs` — the interface.
3. `Infrastructure/Repositories/ThingRepository.cs` — the implementation.
4. `Api/Contracts/ThingRequests.cs` — request records with validation attributes.
5. `Api/Controllers/ThingsController.cs` — the controller.
6. Register the repository in `Api/Program.cs`.
