# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Repository layout

Two independent halves wired together only by an HTTP proxy:

- `frontend/` — React 19 + TypeScript SPA (Vite 8, yarn). Vite dev server proxies `/api/*` to `http://localhost:5000`, so frontend code uses relative URLs (`fetch('/api/npcs')`) and there is no CORS configuration.
- `backend/` — .NET 10 Web API. The `http` launch profile is pinned to port 5000 to match the proxy; don't change one without the other (`frontend/vite.config.ts` ↔ `backend/NpcManagement.Api/Properties/launchSettings.json`).

## Commands

Frontend (run from `frontend/`, uses yarn — not npm):

```sh
yarn dev          # dev server on :5173
yarn build        # tsc -b && vite build — type-check + production build
yarn lint         # ESLint
yarn format       # Prettier --write
yarn test         # Vitest (jsdom), test files live beside source (*.test.ts)
```

Backend (run from `backend/`):

```sh
dotnet build NpcManagement.slnx                               # note: .slnx, not .sln
dotnet run --project NpcManagement.Api --launch-profile http  # serves :5000
```

The backend has no tests yet.

## Backend architecture

Three projects with dependencies pointing inward — `Api → Infrastructure → Domain`:

- `NpcManagement.Domain` — entities and repository interfaces only; references nothing.
- `NpcManagement.Infrastructure` — repository implementations. Currently `InMemoryNpcRepository` (ConcurrentDictionary, singleton — data resets on restart).
- `NpcManagement.Api` — controllers, request contracts (records with DataAnnotations validation in `Contracts/`), and DI registration in `Program.cs`.

New resources follow the NPC slice pattern: entity + interface in Domain, implementation in Infrastructure, contracts + controller in Api, one DI registration in `Program.cs`. Controllers depend only on the Domain interfaces, never on Infrastructure types.

## Frontend architecture

- **Routing**: TanStack Router, file-based. Routes are files in `src/routes/` (`__root.tsx` is the shared layout). `src/routeTree.gen.ts` is generated by the Vite plugin — never edit it; it's ignored by ESLint/Prettier and regenerated by `yarn dev` or `vite build`. Note the build script runs `tsc` *before* vite, so on a fresh clone or after route changes outside dev, run `npx vite build` (or start `yarn dev`) once if `tsc` can't find `./routeTree.gen`.
- **Styling**: Tailwind v4 via the Vite plugin — there is no `tailwind.config`; theme tokens are CSS variables in `src/index.css` (`:root` light, `.dark` dark). Use semantic classes (`bg-background`, `text-muted-foreground`) rather than raw colours.
- **shadcn/ui**: components are vendored source in `src/components/ui/`, added with `npx shadcn@latest add <name>` (v4 CLI; if it prompts interactively, pass `--preset nova`). Edit them directly.
- **Imports**: `@/` maps to `src/` (configured in `vite.config.ts` and both tsconfigs). The tsconfigs use `paths` without `baseUrl` deliberately — TypeScript 6 deprecates `baseUrl`; don't re-add it.

## Lint exceptions (deliberate — don't "fix" the code instead)

`react-refresh/only-export-components` is disabled in `eslint.config.js` for:
- `src/components/ui/**` — shadcn exports helpers (`buttonVariants`) beside components
- `src/routes/**` — the TanStack Router plugin manages HMR for route files itself
